# CLAUDE.md

Guidance for agents working in this repository.

## What this is

FC Турніри: a small web app for EA SPORTS FC tournaments between two players, **S** and **V**. About three people use it. It is a proof of concept that grew from a product spec (summarised below). The UI is in **Ukrainian**; code, comments and docs are in English.

Core features:

- Import tournaments from JSON (prepared with ChatGPT), with validation and a preview. Export back to JSON.
- Enter, edit and clear match results on phone or desktop. Changes sync live to every device.
- Standings, tournament statistics, S vs V comparison, and history across all tournaments (per club, head-to-head).

The app was scaffolded on 2026-10-30, reusing conventions from the sibling project `../web-app` (SOLV, React + PrimeReact). It is fully independent of it; do not import from or modify `../web-app`.

## Runbook

`docs/how-to.md` holds the step lists for common tasks and fixes (deploy, GitHub, import errors, replacing or unlocking a tournament, missing crests or flags, club id drift, backups, Firebase CLI account, emulator). ## Commands

```bash
npm run dev            # http://localhost:3100 against the Firebase project in .env.local
npm run dev:emulator   # same, against the local Firestore emulator
npm run emulator       # Firestore emulator on 127.0.0.1:8080
npm run build          # tsc -b + vite build
npm run lint           # ESLint + Prettier (fix: npx eslint --fix .)
npm test               # domain unit tests (vitest)
npm run test:rules     # firestore.rules tests, emulator must be running
npm run deploy         # build + firebase deploy (hosting, firestore rules)
npm run club-catalog   # rebuild src/constants/clubCatalog.json (crests); add "-- clubs.json" to list unmatched clubs
```

Verify every change with `npx tsc -b`, `npm run lint` and `npm test`. Run `npm run test:rules` after changing `firestore.rules` or anything in `src/source/`.

The emulator needs **Java 21**. On this machine the default `java` is 19; Homebrew's JDK 21 works:

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21 PATH="/opt/homebrew/opt/openjdk@21/bin:$PATH" npm run emulator
```

## Stack

React 19, TypeScript strict, Vite 7, PrimeReact 10 (Lara dark teal theme, which also ships the Inter font), PrimeFlex 3.3, React Router 7, Firebase JS SDK 13 (Firestore and App Check only), zod 4 for import validation, Fluent UI icons, vitest. No Redux, no axios, no backend.

```
    league.ts      groupTable, playoffQualifiers (draw defaults), findLeagueWinner, clubOrigin
    schedule.ts    upcomingMatches (play order), latestResult
    cards.ts       computeDiscipline: bans from yellow and red cards, player name suggestions
    playoff.ts     bracket (computePlayoff), tie winners, replays, champion, playoff reach
    draw.ts        playoff draw: allowed pairings (drawCandidates), random pick (pickDraw)
    standings.ts   records and group tables (tie-breakers)

    history.ts     cross-tournament: summaries, club histories, head-to-head
    exportJson.ts  tournament to JSON file, club catalog
    domain.test.ts
  constants/clubCatalog.json   Generated by scripts/build-club-catalog.ts: crest id, league country, names

  constants/env.ts      Every VITE_* variable is read here and only here
  source/TournamentSource.ts   Every Firestore read and write
  source/firestore.rules.test.ts  rules tests through TournamentSource against the emulator
  hooks/useSaveResult.ts   Saving a score from any screen (group, playoff game, pending extra game)
  hooks/useMatchCards.ts   Adding and removing cards of a stored match
  providers/
    TournamentDataProvider.tsx  ONE live subscription to all tournaments + one to all matches
                                (collection group); every screen reads useTournamentData()
    ToastProvider.tsx           useToast().show(severity, summary, detail)
  ui/            Shared presentational components (barrel: src/ui/index.tsx)
  components/    Layout: AppLayout (sidebar from 768px, bottom nav on phones), PageHeader
  screens/       dashboard, tournaments, tournament-details, history, import-export (lazy routes)
  routes/AppRouter.tsx
  styles/main.css

```

Layering: screen, then `useTournamentData()` for reads or a `TournamentSource` function for writes. Score entry always goes through `useSaveResult`, so the playoff rules (stale extra games, creating a pending extra game) apply everywhere. Statistics are always computed in `domain/` from match results and never stored.

## Data model (Firestore)

```
tournaments/{tournamentId}
  id, schemaVersion (1), number, name, game, format ("sv-groups-4x4" | "sv-league-40"),
  status ("planned" | "active" | "completed"),
  players [{id:"S"|"V", name}], groups [{id, name}],
  clubs [{id, name, country?, owner:"S"|"V", group, pot?, code?}]  (pot and code: league only),
  createdAt, updatedAt (server timestamps)

tournaments/{tournamentId}/matches/{matchId}
  group match:   stage "group", group, matchday, home, away, result, updatedAt
  playoff game:  stage "playoff", round ("QF" | "SF" | "F"), tie, game,
                 home, away, result, updatedAt
  result: {home, away} | null
  cards?: [{id, club, player, type: "yellow" | "red"}]   (both stages)
```

- `IMatch` is a union (`IGroupMatch | IPlayoffMatch`) on `stage`. Use `groupMatches()` / `playoffMatches()` from `domain/playoff.ts` to narrow.
- Playoff: 4 QF ties, 2 SF ties, 1 final. Ids are fixed: `{round}{tie}-{game}` (`QF1-1`), checked by the rules and the import. A game document exists only once both clubs of the tie are picked, so `home`/`away` are never null.

- `result: null` means not played. `{home: 0, away: 0}` is a played 0:0.
- Club **ownership is per tournament** (stored on the tournament's club entry). The same club id can be S in one tournament and V in another.
- Club ids are global slugs (`real-madrid`) and join a club's history across tournaments. The import warns when a known club name arrives with a new id.
- Matches are separate documents so the rules can validate each score write and two people can enter different matches at once.
- `firestore.rules`, `TournamentSource.ts` and `domain/schema.ts` describe the same shapes. **Change them together**, then run `npm run test:rules`.

## Decisions already made (do not re-open without the user)

- **No authentication, by the user's explicit choice.** Anyone with the link can do anything the rules allow. Protection is the rules plus optional App Check (enabled when `VITE_RECAPTCHA_SITE_KEY` is set). Do not add sign-in screens.
- Rules allow on a tournament: create (exact shape, `champion` optional), update of `status` only, of `name` only (any status; pencil button in `TournamentActions`, `RenameTournamentDialog`) or of `champion` only (the latter not when completed), delete unless completed. On a match: create during import or while active; update while active (group: `result` only; playoff: `home`, `away`, `result`); delete together with the tournament, and playoff games also on their own while not completed. Completed tournaments are locked; the UI "Розблокувати" sets them back to active.
- Standings order: points (3/1/0), goal difference, head-to-head among the tied clubs (points, goal difference, goals), goals scored, name. In this format clubs of the same player never meet, so head-to-head often has no data and goals scored decides.
- **Crests and flags** (2026-10-30): crests come from ESPN's public team lists (top European leagues and their second divisions, smaller EA FC leagues, UEFA competitions; about 500 clubs), national teams (ESPN's friendlies list, about 200; their image is the flag, under ESPN's `countries` path, see `nation` in the catalog) and single clubs from no current list (`EXTRA_TEAMS`). ESPN sends no CORS headers, so `scripts/build-club-catalog.ts` builds a static catalog that ships with the app; nothing is stored in Firestore. Clubs match by id, then by name (`normalizeClubName`); mismatches get an entry in the script's `ALIASES`. Images are hotlinked from `a.espncdn.com` (dark variant, resized by its CDN). An unknown club shows a letter circle, and the import preview lists clubs without a crest. Flags: `ui/CountryFlag.tsx` (flag-icons, named-import registry like FluentIcon); the country from the tournament file wins over the catalog's league country. `ClubLabel` shows the crest always and the flag with `showFlag` (tables and lists, not match rows). A national team (`nation` in the catalog) shows no extra flag anywhere, since its crest is the flag.
- **Play order** (confirmed by the user on 2026-10-30): group matches by matchday, then each playoff round with every first leg before the second legs (QF1, QF2, QF3, QF4 first legs, then QF1 second leg, ...), extra games after the legs. `upcomingMatches` implements it.
- **Dashboard quick entry** ("Матчі зараз", active tournament only): the result changed last and the next match, both editable; the next two before the first result. Its rows use `MatchRow showcase`: large faded crests and flags of both clubs behind the row (`ui/MatchBackdrop.tsx`). Above a second leg or an extra game it shows the tie's earlier games, and the aggregate when there are two or more (`earlierTieGames` in `domain/playoff.ts`, `dashboard/components/EarlierGames.tsx`).
- `MatchRow` with a non-empty `footer` (cards) puts ✓ and × on the footer line, right of "+ Картки", on every screen width (CSS in `styles/main.css`, `:has(> .match-row__footer:not(:empty))`).
- Player badges: S is red (`--red-500`), V is blue (`--blue-500`), see `ui/PlayerBadge.tsx` and `.player-badge` in `styles/main.css`.
- Look: dark "stadium" theme. Teal is the accent (kept apart from S red and V blue). Cards are `.app-card` (translucent over the red/blue background glow), section titles `.section-title`, the dashboard and tournament page open with `ui/TournamentHero.tsx` (scoreboard on a `.pitch` background). Light-theme utility colours such as `bg-red-50` do not work on dark; use `.notice`, `.notice--error`, `.notice--warning`.
- Only the final score is stored. No dates, no extra time, no penalties.
- **Playoff** (decided with the user on 2026-10-30, legs added the same day): every tie is filled in by hand from the tournament's clubs; nothing advances automatically.
  - **Quarter-finals and semi-finals have two legs** (in a league also KO and R16), created together as soon as both clubs are picked: game 1 at the first club, game 2 at the second. **The final is one game.** `PLAYOFF_ROUNDS[].legs` in `domain/playoff.ts` holds this.
  - **The aggregate decides** (goals over all games of the tie). When every game is played and the aggregate is level (or the final is a draw), an extra game is due (`pendingReplay`), shown in the UI and stored only once its result is saved. Home and away alternate from game to game (`gameTeams`).
  - **Picker rule** (`canPair`, `strictPairing` per round): once one club of a quarter-final tie is picked, the other must belong to the other player and come from a different group. Semi-finals and the final are free, because the remaining winners may share a player or group. The import does not enforce this rule (older tournaments may differ).
  - Teams of a tie can be changed later; every game gets the pair in the alternating order. Correcting or clearing a result that makes extra games pointless deletes them, after a confirmation (`staleExtraGames`).
  - The import also accepts older files with single-game ties and replays with the same home club.
  - **Draw** (added 2026-10-30): a "Жеребкування" button per round (`PlayoffDrawDialog.tsx`), offered until the first game of the round is played. Quarter-finals: pick 4 S and 4 V clubs, every pair is S against V from another group (no draw if impossible). Semi-finals: the 4 quarter-final winners, once every quarter-final is decided; the same rule is followed as far as the clubs allow (fewest same-player or same-group pairs). The pairing, tie order and home club are random; the result is shown with "Ще раз" and saved only on "Підтвердити" (`applyPlayoffDraw`), replacing ties already picked. No draw for the final.
- **Champion** (decided with the user on 2026-10-30): two sources. The winner of a decided final always wins; otherwise `tournament.champion`, a club picked by hand on the playoff tab (`ChampionPanel.tsx`, `setTournamentChampion`) or set in the imported JSON. `findChampionClub` in `domain/history.ts` applies this rule and everything (hero, dashboard, history, titles, club reach) goes through it. Picking needs an active tournament; a completed one must be unlocked first.
- **Titles** count only **completed** tournaments (`countsAsTitle` in `domain/history.ts`). A tournament in progress may show a champion but wins no title until it is completed. Shown in `ui/TitlesCard.tsx` on the dashboard and at the top of History.
- **Planned tournaments** are future tournaments: imported with status `planned`, listed under "Заплановані" (always visible), read-only (schedule visible, no results, playoff or champion; enforced by `isActive` in the rules). "Почати турнір" is disabled while another tournament is active. There is no in-app tournament creator yet; planned tournaments come from JSON import.
- **Table extras** (2026-11-12): `StandingsTable` takes `form` (`computeForm` in `domain/standings.ts`, last 5 group results as В/Н/П chips, newest first, green, yellow and red) and `next` (`computeNextMatches`, an outlined "?" chip before them while active); `ui/FormChips.tsx` shows a small match card (matchday, outcome, both clubs, score) on mouse hover or on a tap and `chances` (`computePlayoffChances` in `domain/chances.ts`: share of 1000 simulated rests of the group stage, random scores, clubs of equal strength, in which a club takes a playoff place; via `hooks/usePlayoffChances.ts`, fixed seed, only while active with at least one result and one match left). Shown as "<1%" and ">99%" at the ends, never 0 or 100. The table is a size container (`.standings-wrap`): below 640px the goals column hides, below 540px the form shows only the newest chips, below 420px it hides; below 400px flags and pots hide and names truncate.
- **Matches tab filters**: matchday buttons plus "Усі", a club picker (switches to all matchdays) and "Лише незіграні".
- **Динаміка tab for every format** (`TimelineTab.tsx`): a league shows the one table, a group tournament has a group switch (taller rows for 4 clubs; playoff places are the first two). History has "S проти V від турніру до турніру" (`PlayersProgressChart.tsx`, `computePlayerProgress` in `domain/history.ts`): running wins, points, goals or titles after each tournament, hover or tap for the numbers. `hooks/useWidth.ts` measures both charts.
- History, Клуби: "Усього" or "За матч" (`ClubsHistory.tsx`). Per match shows win, draw and loss shares, goals for and against, goal difference and points per match, sorted by points per match, only for clubs with at least 1, 5 (default), 10 or 20 matches.
- **Insights** (added with the user on 2026-11-18; all computed in `domain/insights.ts` and `domain/achievements.ts`, nothing stored):
  - Dashboard: "Форма S і V" (last 10 S against V matches as coloured squares, wins in a row and the longer unbeaten run per player, `recentDuels`, `currentStreaks`), "Ювілеї" (next round numbers of goals, matches and wins over all tournaments and those reached in this tournament, `computeMilestones`; steps of 25 under 100, 100 under 1000, then 250), "Підсумок туру N" (last complete matchday, `latestMatchdayRecap`) with "Поділитися" (`utils/shareImage.ts` draws a PNG on a canvas, without crests because ESPN sends no CORS headers; the phone share sheet when it takes files, otherwise a download), "Рекорди турніру", "Досягнення турніру".
  - Hero: chance of S or V ending the group stage (or league) with more wins (`computeWinsRace`, 1000 simulations, `hooks/useWinsRace.ts`), on the dashboard and the tournament page while a group match is left.
  - Statistics tab: "Гонка S і V по турах" (`computeRace`, `ui/DuelLineChart.tsx`), "Частота рахунків" (0 to 10+, winner's goals first), "Голів у матчі" (matches per total goals, 0 to 12+, goal fests marked), "Кошики ліги" (league only: points per match per pot, the surprise and the disappointment against the places a pot usually takes). Home and away statistics were removed at the user's request (not relevant for them); the top tiles show goal fests and the most goals in a match instead.
  - Achievements (`computeAchievements`): Розгром (win by 5+), Голеада (10+ goals in a match; the user's games score high), Залізобетонний захист (1 goal or fewer conceded in a match), Серія (5 club wins in a row), Камбек (playoff tie won after losing game 1), Ідеальний тур (one player wins every match of a matchday), Без поразок (club unbeaten in the whole group stage), Чиста гра (fewer card points after the group stage). The dashboard shows one tile per kind (S:V count and the latest earner) so a frequent kind does not hide the others; kinds nobody has earned yet follow greyed out with their rule; "Показати всі N" expands a tile across the row with every achievement of that kind, newest first (a drawn goal fest lists both clubs); History shows the totals and the milestones.
- **Goal replay on the hero** (2026-11-18, `ui/GoalReplay.tsx`): a ball leaves one of the goal dots and flies into the net with a flash in the scorer's colour. Each player has their own timer and both start together: the player with more goals shoots every second, the other at a proportionally longer interval (13 against 10 goals: every 1 s against every 1.3 s), as the user asked; not every goal of the tournament is replayed (about 200 per tournament). Off with reduced motion.
- Clicking a club in a group or league table (tournament tab and dashboard) opens `ui/ClubMatchesDialog.tsx`: place, record without the playoff, and every match of the club in that tournament with cards, read-only. `StandingsTable` takes `onClubClick`.
- Playoff games count in S vs V, tournament stats, club history and head-to-head; never in group tables. A "Враховувати плей-офф" checkbox (`ui/PlayoffToggle.tsx`, on by default, shown only when there are playoff games) on the tournament statistics tab and on History switches to group-stage numbers (`statMatches` in `domain/playoff.ts`, the `includePlayoff` argument in `domain/history.ts`). Champions, titles and playoff reach always use every match.
- **Cards and bans** (decided with the user on 2026-10-31): yellow and red cards per match, for a footballer typed by name (`playerKey` matches names without case; names used before are suggested per club). Rules in `computeDiscipline` (`domain/cards.ts`): a red card or two yellows in one match ban the next match of the club; the second yellow of the tournament bans the next match; once a footballer has served any ban, every further yellow bans the next match. Bans are 1 match. Yellows carry over from groups or league into the playoff. Cards count as soon as they are entered, with or without a result. `ui/MatchCards.tsx` shows the cards, the "+ Картки" dialog (both clubs side by side; a typed name or a tap on a footballer booked before adds a yellow, the card icon switches it to red, one save for all via `addMatchCards`) and the "Пропускає матч" line, in `MatchRow`'s `footer` on the matches tab, the dashboard (quick entry and next matches) and the playoff ties. Card writes use `arrayUnion`/`arrayRemove` and leave `updatedAt` alone, so a card does not change the dashboard's latest match; the rules allow a `cards`-only update (list of at most 30) while active. `TournamentHero` shows each player's yellow and red totals under the S and V badges once the tournament has a card; the badges are always drawn as faces instead of the letter, the letter under them (`ui/PlayerMoodBadge.tsx`, `cardMoods` in `domain/stats.ts`, decided with the user on 2026-11-18): card points are yellow 1 and red 3, and the difference to the other player picks one of 8 moods (angel at -5 or less, happy -4 to -1, polite at 0 including no cards, neutral 1 to 2, displeased 3 to 4, annoyed 5 to 7, angry 8 to 11, furious 12 or more); the statistics tab lists the most carded footballers per player.
- **League playoff** (decided with the user on 2026-11-12, league only; the group format keeps QF, SF, final unchanged): after the league the 4 best S and 4 best V clubs go straight to the round of 16 (`R16`, `playoffQualifiers`); the next 8 of each player (places 5 to 12 among the player's clubs, `leagueKnockoutClubs`) play the knockout round (`KO`, "Стикові матчі"); places 13 to 20 are out. Both new rounds have 8 ties and two legs (`PLAYOFF_ROUNDS[].leagueOnly`, `playoffRounds(league)`; `computePlayoff(matches, league)` includes them for a league or when a game of them exists). Draws: KO is S against V at random (`pickKnockoutDraw`; the picker enforces it, `isStrictPairing`), once every league match is played; R16 is every direct club against a KO winner, S against V as far as the winners allow (`pickRound16Draw`), the winner hosting game 1 and the direct club game 2; QF and SF draw from the previous round's winners with the fewest same-player pairs. In a league only KO is strict; in groups only QF. The table marks direct places teal and KO places grey; the chance column is the chance of a direct place. The import refuses KO and R16 outside a league; the rules allow ties 1 to 8 for them.
- **League format `sv-league-40`** (decided with the user on 2026-10-30): 40 clubs in one group `L`, 4 pots of 5 S + 5 V, 8 matchdays, 160 matches; the draw comes from ChatGPT (`docs/chatgpt-league-prompt.md`) and `validateSvLeague40` checks every rule. **Two champions**: the league table winner once every league match is played (`findLeagueWinner`, silver `ChampionBadge league`), and the playoff champion as before. Titles count the playoff champion; league wins are counted on their own line in `TitlesCard`. The playoff runs through the knockout round and the round of 16 (see League playoff). The "Групи" tab is called "Таблиця". A league also has the "Динаміка" tab (`TimelineTab.tsx`, also used for groups): a bump chart drawn in plain SVG (no chart library) of each club's place after every matchday (`computeTimeline` in `domain/timeline.ts`), lines in the player's colour, crests at the tips, play/pause and a slider, matchdays labelled М1, М2. Real results show only the matchdays played; "Симуляція" fills unplayed matches with random scores (`simulateResults`, seeded, nothing stored).
- The tournament **champion** is the winner of the final. History shows titles S : V.

## Conventions (carried over from web-app)

- `@/` alias for `src/`; relative imports only inside the same folder. `import type` for type-only imports.
- Interfaces are `I`-prefixed. Screen folders are kebab-case. Barrel files: `src/ui/index.tsx`, `src/components/index.ts`, `src/domain/index.ts`, `src/providers/index.ts`, `src/utils/index.ts`.
- No `any`, `@ts-ignore` or needless `!`/`as`.
- PrimeReact components directly (`Button`, `Dropdown`, `DataTable`, `Dialog`, `TabView`, ...), never a bare `<button>`. The only raw form element is the hidden `<input type="file">` in the import panel. Plain `<img>` is used for crests and flags.
- PrimeFlex fixed widths stop at `w-30rem` (`md:w-40rem` does not exist); wider dialogs use `.dialog-wide`.
- Icons: `<FluentIcon name="..." />` from `@/ui`. It uses a **named-import registry** (`ui/FluentIcon.tsx`) so only the listed icons are bundled. To use a new icon, add it to the `ICONS` map.
- Styling: PrimeFlex classes and theme CSS variables. No hex or rgb literals in components. App-specific classes are in `styles/main.css`. Inline `style` only for computed widths.
- Modals: `Dialog` with `showHeader={false}`, title in the body, absolute close button (see `screens/history/components/ClubHistoryDialog.tsx`). Confirmations use `confirmDialog` from `primereact/confirmdialog` (`<ConfirmDialog />` is mounted in `App.tsx`).
- UI text is written directly in Ukrainian in the components (no i18n library). `utils/format.ts` has `plural()` for Ukrainian plural forms.
- Prettier: 80 columns, double quotes, trailing commas es5.
- After making code changes, end with a suggested commit message. Do not commit unless the user asks.

## Behaviour worth knowing

- Completing a tournament goes through `ui/CodeConfirmDialog.tsx`: the confirm button unlocks only after typing a random 4-digit code. Mount it only while open (a new code each time). Reuse it for other risky actions.
- **Testing in a browser:** the user often has `npm run dev` running on port 3100 against the REAL database. Run emulator test servers on another port (`--port 3101 --strictPort`) and block requests to `firestore.googleapis.com` in the test, so test data never reaches production.
- `MatchRow` keeps a local draft of the score. The parent gives it `key={matchId:score}`, so a remote change remounts the row with the new stored value. Enter saves, Escape reverts.
- Saving does not wait for the server: Firestore updates the local snapshot at once and the promise settles later (much later when offline). Errors (for example a rules rejection) show a toast and the snapshot rolls back.
- With no Firebase config, `App.tsx` renders `FirebaseSetupNotice` instead of the app.
- `vite:preloadError` in `main.tsx` reloads once after a deploy removes old lazy chunks.
- **Icons and link previews** (2026-10-31): `public/` holds `favicon.svg` (S and V badges), PNG icons (32, 180, 192, 512, maskable 512), `site.webmanifest` and `og-image.png` (1200x630). `index.html` has the description, Open Graph and Twitter tags with absolute `https://eafc-tournament-75465.web.app/...` URLs, and `robots noindex` (no sign-in, so the app stays out of search results). The PNGs were rendered once from HTML in headless Chrome; there is no build step for them.
- Firestore reads: the whole history loads on each app open (tournaments + all matches). With dozens of tournaments that is about a thousand reads per open, well inside the free 50k per day.
